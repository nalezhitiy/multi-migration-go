# Database Migrations

CLI-інструмент для керування SQL-міграціями баз даних на Go з використанням [Goose](https://github.com/pressly/goose).

Підтримувані СУБД:
- PostgreSQL
- MariaDB
- ClickHouse

Кожна база даних має власний каталог міграцій. Команди виконуються лише для однієї явно вказаної БД.

## Вимоги

- Docker
- Docker Compose
- GNU Make

## 1. Підготовка та запуск

Створи файл конфігурації середовища на основі прикладу:

```bash
cp .env.example .env
```

Заповни `.env` необхідними змінними середовища, зокрема рядками підключення до баз даних.

Збери контейнери:

```bash
make container@build
```

Переконайся, що потрібна база даних запущена та доступна для підключення.

## 2. Конфігурація

Приклад конфігурації мігратора:

```yaml
migrations:
  dir_name: migrations
  table_name: migrations_goose

databases:
  postgres-main:
    dialect: postgres
    dsn: ${APP_POSTGRES_DSN}

  mariadb-main:
    dialect: mysql
    dsn: ${APP_MARIADB_DSN}

  clickhouse-main:
    dialect: clickhouse
    dsn: ${APP_CLICKHOUSE_DSN}
```

### Параметри

| Параметр | Опис |
|---|---|
| `migrations.dir_name` | Кореневий каталог міграцій |
| `migrations.table_name` | Таблиця Goose для обліку застосованих міграцій |
| `databases` | Перелік доступних баз даних |
| `dialect` | Діалект відповідної СУБД |
| `dsn` | Рядок підключення до бази даних |

Значення `dsn` передаються через змінні середовища, визначені у `.env`.

Назви `postgres-main`, `mariadb-main` і `clickhouse-main` використовуються в командах як ідентифікатори баз даних.

## 3. Структура міграцій

Для кожної бази даних використовується окремий каталог (приклад який добавлений в проект, його можна видалити разом з директорією `revisions`):

```text
migrations/
├── postgres-main/
│   └── 20261012120000_create_users.sql
├── mariadb-main/
│   └── 20261012121000_create_products.sql
└── clickhouse-main/
    └── 20261012122000_create_products_views.sql
```

Міграції з одного каталогу не застосовуються до інших баз даних.

**Підтримуються лише SQL-міграції.** Кожен файл має містити секції `-- +goose Up` і `-- +goose Down`.

## 4. Створення міграції

Створи міграцію для потрібної бази даних:

```bash
make migrations@create DB=postgres-main name=create_users.sql
```

Для інших СУБД:

```bash
make migrations@create DB=mariadb-main name=create_products.sql

make migrations@create DB=clickhouse-main name=create_products_views.sql
```

Команда створить SQL-файл у каталозі вибраної бази даних, додавши до назви часовий префікс.

### Приклад SQL-міграції

Файл `create_users.sql`:

```sql
-- +goose Up
CREATE TABLE users (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(150) NOT NULL,
    email VARCHAR(320) NOT NULL UNIQUE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- +goose Down
DROP TABLE IF EXISTS users;
```

- `Up` — зміни, які потрібно застосувати.
- `Down` — зміни для скасування міграції.

**Важливо:** синтаксис SQL залежить від СУБД. Наприклад, типи даних і конструкції PostgreSQL не завжди сумісні з MariaDB або ClickHouse.

Перед запуском перевір створений файл і його SQL.

## 5. Запуск міграцій

Щоб застосувати всі невиконані міграції PostgreSQL:

```bash
make migrations@up DB=postgres-main
```

Для MariaDB:

```bash
make migrations@up DB=mariadb-main
```

Для ClickHouse:

```bash
make migrations@up DB=clickhouse-main
```

### Основні команди

| Команда | Призначення |
|---|---|
| `migrations@up` | Застосувати всі невиконані міграції |
| `migrations@up-by-one` | Застосувати одну наступну міграцію |
| `migrations@up-to` | Застосувати міграції до вказаної версії |
| `migrations@down` | Скасувати останню застосовану міграцію |
| `migrations@down-to` | Скасувати міграції до вказаної версії |
| `migrations@redo` | Повторно виконати останню міграцію |
| `migrations@reset` | Скасувати всі застосовані міграції |
| `migrations@status` | Показати статус міграцій |
| `migrations@version` | Показати поточну версію |
| `migrations@fix` | Перенумерувати міграції відповідно до правил Goose |

Приклади:

```bash
# Застосувати наступну міграцію
make migrations@up-by-one DB=postgres-main

# Переглянути статус
make migrations@status DB=postgres-main

# Переглянути поточну версію
make migrations@version DB=postgres-main

# Повторно виконати останню міграцію
make migrations@redo DB=postgres-main
```

Для команд `up-to` і `down-to` передай номер цільової версії відповідно до аргументів, які приймає твій Makefile. Наприклад, якщо він використовує параметр `version`:

```bash
make migrations@up-to DB=postgres-main version=20261012120000
make migrations@down-to DB=postgres-main version=20261012120000
```

## 6. Важливі правила

- **Параметр `DB` обов'язковий.** За один запуск можна працювати лише з однією базою даних; режим `all` не підтримується.
- Не змінюй уже застосовані міграції. Для нових змін створюй новий файл.
- Перевіряй SQL перед запуском у production.
- Команди `down`, `redo` та особливо `reset` можуть змінювати або видаляти дані.
- DDL-операції не в усіх СУБД підтримують транзакційний відкат. Якщо міграція завершилася помилкою, перевір стан схеми та таблиці `migrations_goose` перед повторним запуском.
- Складні або масові перетворення даних краще виконувати окремими Go-інструментами, а не вбудовувати в SQL-міграції.
